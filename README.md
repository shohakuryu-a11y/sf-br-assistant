# BR アシスタント

© 2026 Liu. All rights reserved.

条件ロジックを自然な文章で書くだけで、そのまま設定に使える SAP SuccessFactors ビジネスルールの設計案が得られます。設計案で使っている項目・選択肢の値・イベント事由・関数がテナントで使えるかどうかも、1 つずつ検証します。

**AI の API は一切呼び出さないため、無料で使えます。** 確定的な処理（概念の分解、項目の検索、プロンプトの組み立て、検証）はすべてアプリが行い、「ルールを設計する」部分だけを、普段使っている AI チャット（Claude、ChatGPT など）に任せます。プロンプトをコピーし、AI の回答を貼り付けると、アプリが自動で検証します。

> 画面の言語は日本語です。デモデータはすべて架空のテナント Demo Corp のもので、実在する顧客のデータは含まれていません。

## 1. クイックスタート

1. `index.html` をダブルクリックしてブラウザで開きます（インストールは不要です）
2. スタート画面が表示されたら、画面のどこかをクリックして開始します
3. 「ルール作成」で入力例を 1 つクリック →「プロンプトを作成」→ ステップ 3 で「サンプルの回答を入れる」→「取り込んで検証」

AI を使わなくても、一連の流れを試せます。実際に使うときは、ステップ 3 を「プロンプトをコピー → AI チャットに貼り付けて送信 → 回答を貼り付ける」に置き換えます。

## 2. 機能説明（分類別）

### 2.3 次の操作のガイド（レーザーの枠）

次に操作すべき入力欄やボタンの枠を、グリーンからティールに変わるレーザーが時計回りに周回し、やわらかい緑の光が広がります。光るのは常に 1 か所だけで、1 つ操作を終えると次の場所に移ります。

| 画面 | ガイドの順番 |
| --- | --- |
| ルール作成 | 要件の入力欄 →「プロンプトを作成」→「プロンプトをコピー」→ AI の回答の入力欄 →「取り込んで検証」→（エラーがある場合）「修正プロンプトをコピー」→ AI の回答の入力欄 →「取り込んで検証」…。検証に合格すると表示されなくなります |
| ルール検証（JSON） | JSON の入力欄 →「検証を実行」→（エラーがある場合）「修正プロンプトをコピー」→ JSON の入力欄 |
| ルール検証（文章） | ルール案の入力欄 →「変換プロンプトを作成」→「プロンプトをコピー」→「AI の回答を貼り付ける」 |
| 項目カタログ | 項目やオブジェクトを変更すると「保存」が光ります。オブジェクトや項目の追加では、ID とラベルを入力すると「追加する」が光ります |

### 2.4 ルール作成（要件からルールを作る）

4 つのステップで進めます。終わったステップは番号が緑になります。

| ステップ | 機能 |
| --- | --- |
| 1 要件を入力 | 業務上の要件を入力します。下のボタンで入力例を入れられます |
| 2 AI に送る | **ローカル解析の結果**：見つかった概念、候補の項目とその理由<br>**プロンプトに含めるデータ**：「項目カタログ全体を含める」がオンのときはカタログ全体を含めます。オフのときは、下で選んだオブジェクトだけを含めます（最初は要件に関係しそうなオブジェクトが選ばれています）<br>**プロンプトを表示**：プロンプト全文と文字数を確認できます<br>**プロンプトをコピー** / **共有**（ブラウザが対応している場合のみ表示） |
| 3 AI の回答を貼り付け | AI の回答を貼り付けます（説明文が含まれていても、JSON の部分だけを取り出します）。入力例を使った場合は「サンプルの回答を入れる」が表示されます |
| 4 検証結果 | **判定**：合格 / 問題の件数<br>**チェック項目**：8 項目のチェック結果（エラーがある場合に表示）<br>**ルール**：IF / ELSE IF / THEN / ELSE のルールカード。項目は「オブジェクト.項目」と ID で表示されます<br>**前提**：AI が置いた解釈の前提<br>**項目の解決**：要件の言葉と項目の対応、種類（直接対応 / 近い項目 / 派生概念）、確信度のバー。70% 未満の場合は候補の確認を促します<br>**新規に必要な設定**、**リスク**<br>**修正を依頼する**（エラーがある場合）：「修正プロンプトを表示」で全文を確認、「修正プロンプトをコピー」/「共有」<br>**JSON をコピー**、**新しい要件**（最初からやり直す） |

「取り込んで検証」を実行するたびに、結果は合否にかかわらず履歴に自動保存されます。

### 2.5 ルール検証（既存の設計案を検証する）

上部で 2 つのモードを切り替えます。

| モード | 機能 |
| --- | --- |
| JSON・AI の回答 | JSON または AI の回答全体を貼り付けて「検証を実行」。結果の表示はルール作成のステップ 4 と同じです。エラーがある場合は「修正プロンプトを表示」で全文を確認し、「修正プロンプトをコピー」/「共有」できます。「履歴に保存」で手動保存します。最初に入っているサンプルにはわざと誤りを入れてあるので、そのまま試せます |
| 文章のルール案 | 文章で書いたルール案を貼り付けて「変換プロンプトを作成」→ 変換用プロンプトを表示・コピー・共有 → AI の回答を貼り付けるときは「AI の回答を貼り付ける」をクリックすると、JSON モードに切り替わります |

### 2.6 履歴

| 機能 | 説明 |
| --- | --- |
| 一覧 | 件数と、各履歴のタイトル・日時を表示します。合格／不合格のアイコンは、毎回**現在のカタログ**で検証し直した結果なので、カタログを変えると結果も変わります。最大 50 件まで保存されます |
| 詳細 | 行をクリックすると開きます：要件の原文、検証し直した結果の全体、「JSON をコピー」、「修正プロンプト」（エラーがある場合、コピー）、「この履歴を削除」 |
| 1 件削除 | 行の右端のゴミ箱をクリック → 赤い「削除」に変わる → 3 秒以内にもう一度クリックで削除。クリックしなければ 3 秒で元に戻ります |
| すべて削除 | 一覧の下の「すべての履歴を削除」。同じく 2 回クリックで確定します |

削除した履歴は元に戻せません。

### 2.7 項目カタログ

カタログは 2 つのレイヤーでできています。**同期レイヤー**（`data/catalog.js`、全員で共有）と、**手動レイヤー**（アプリで行った変更。このブラウザにだけ保存）です。各オブジェクトと項目には出どころを示すラベルが付きます：ラベルなし = 同期、「変更済み」= 変更あり、「手動追加」= 手動で追加、「無効」= 無効化済み。

**カタログのトップ**

| 機能 | 説明 |
| --- | --- |
| オブジェクト一覧 | Employee Central / Foundation Object / カスタム MDF（/ その他）に分けて、項目数と変更数を表示します |
| 検索 | ラベル・同義語・英語ラベル・ID・説明で検索します。オブジェクトと項目の両方が対象です |
| 「オブジェクトを追加」 | 右上と一覧の下にあり、新しいオブジェクトを追加します |
| 「管理」 | 管理パネルを開きます（後述） |

**オブジェクト**

| 操作 | 説明 |
| --- | --- |
| 表示 | オブジェクトの画面に、すべての項目と「アクセスできるオブジェクト」を表示します |
| 追加 | オブジェクト ID（英字で始まる半角英数字とアンダースコア）、日本語ラベル、英語ラベル（任意）、種類（EC / Foundation / MDF）、アクセスできるオブジェクト（複数選択）を入力して「追加する」 |
| 編集 | オブジェクトの画面右上の「編集」：日本語ラベル、英語ラベル、種類、アクセスできるオブジェクトを変更して「保存」。オブジェクト ID は、項目の参照と履歴に使われているため変更できません |
| 変更履歴 | 編集画面に変更が 1 件ずつ記録され、それぞれ「取り消す」で元に戻せます |
| 削除 | 編集画面下部の「このオブジェクトを削除」を 2 回クリックします。<br>**同期レイヤーのオブジェクト**：非表示になり、プロンプト・検証・書き出す catalog.js から外れ、ほかのオブジェクトの「アクセスできるオブジェクト」からも外れます。「管理」から復元できます<br>**手動で追加したオブジェクト**：手動で追加した項目とともに完全に削除され、元に戻せません |

**項目**

| 操作 | 説明 |
| --- | --- |
| 表示 | データ型、picklist、英語ラベル、ソース。選択肢の項目では、すべての値を一覧表示します |
| 編集 | 日本語ラベル、意味の説明、同義語（「、」またはカンマ区切り）、有効スイッチを変更して「保存」。プロンプト作成時の検索は、ラベル・説明・同義語を使います。無効にした項目は、プロンプトで使用不可と伝え、バリデーターもエラーにします |
| 変更履歴 | 変更はすべて記録され、「取り消す」で元に戻せます |
| 追加 | オブジェクトの画面右上の「項目を追加」：項目 ID、日本語ラベル、英語ラベル、データ型、picklist（選択肢の場合）、意味の説明、同義語 |
| 削除 | 手動で追加した項目のみ：項目の画面下部の「この項目を削除」を 2 回クリックします |

**管理パネル**

| 機能 | 説明 |
| --- | --- |
| 集計 | テナント、カタログのバージョン、変更・追加・削除したオブジェクト数、変更・追加した項目数 |
| 削除したオブジェクト | 削除した同期レイヤーのオブジェクトの一覧。「復元」で元に戻せます |
| catalog.js を書き出す | すべての変更を反映したカタログ全体を書き出します。リポジトリの `data/catalog.js` と置き換えると、全員に反映されます |
| 変更だけを書き出す（JSON） | このブラウザの変更（オブジェクト、項目、変更履歴）だけを書き出します。別の PC に移すときに使います |
| 変更を読み込む（JSON） | 上の JSON を読み込みます。このブラウザの変更は、読み込んだ内容で**置き換わります** |
| この端末の変更をすべて消す | このブラウザのカタログの変更をすべて消します。2 回クリックで確定します |

### 2.8 バリデーター（8 項目のチェック）

| チェック項目 | 内容 |
| --- | --- |
| JSON の構造 | 必要なキーがそろい、形式が正しい。不明なキーは黙って無視せず、エラーとして報告します |
| 項目の存在と有効性 | 参照する項目がカタログにあり、無効化されていない |
| base object からのアクセス | 項目が base object またはそのアクセス先のオブジェクトにある |
| データ型の一致 | 比較・代入の両辺のデータ型が一致している |
| 選択肢の値 | picklist のコードが存在し、有効である |
| イベント事由 | イベント事由が存在し、有効である |
| 関数の使い方 | 関数が存在し、引数の数と型が正しい |
| event | event が使用可能な値である |

## 3. 操作ガイド（作業別）

### 3.1 要件からルールを 1 つ作る

1. サイドバーの「ルール作成」を開き、ステップ 1 に要件を入力します（または入力例をクリック）
2. 「プロンプトを作成」をクリックします
3. ステップ 2 で候補の項目を確認します。カタログが大きい場合は「項目カタログ全体を含める」をオフにし、必要なオブジェクトだけを選びます
4. 「プロンプトをコピー」をクリックし、Claude や ChatGPT などのチャットに貼り付けて送信します
5. AI の回答を全部コピーしてステップ 3 の入力欄に貼り付け、「取り込んで検証」をクリックします
6. ステップ 4 の結果を確認します。特に「前提」と、確信度 70% 未満の「項目の解決」を確認してください
7. 結果は「履歴」に自動保存されます

### 3.2 エラーのある設計案を直す

1. 検証結果の下の「修正プロンプトを表示」で、内容を先に確認できます
2. 「修正プロンプトをコピー」をクリックし、**同じ** AI チャットに貼り付けます
3. AI が返した新しい回答を入力欄（ルール作成ではステップ 3、ルール検証では JSON の入力欄）に貼り付けて、もう一度検証します
4. 「検証に合格しました」と表示されるまで繰り返します

### 3.3 既存の JSON や文章のルール案を検証する

- **JSON**：「ルール検証」→「JSON・AI の回答」→ 貼り付け →「検証を実行」→ 必要なら「履歴に保存」
- **文章のルール案**：「ルール検証」→「文章のルール案」→ 貼り付け →「変換プロンプトを作成」→「プロンプトをコピー」して AI に送信 →「AI の回答を貼り付ける」→ 回答を貼り付け →「検証を実行」

### 3.4 履歴を見る・整理する

- 見る：「履歴」→ 行をクリック
- 1 件削除：行の右端のゴミ箱をクリックし、赤い「削除」をもう一度クリック
- すべて削除：一覧の下の「すべての履歴を削除」を 2 回クリック

### 3.5 項目カタログをメンテナンスする

- **オブジェクトを追加**：「項目カタログ」→「オブジェクトを追加」→ 入力 →「追加する」→ 新しいオブジェクトの画面で「項目を追加」から項目を登録
- **オブジェクトを変更**：オブジェクトを開く →「編集」→ 変更 →「保存」
- **オブジェクトを削除**：オブジェクトを開く →「編集」→「このオブジェクトを削除」を 2 回クリック
- **誤って削除したオブジェクトを戻す**：「管理」→「削除したオブジェクト」→「復元」
- **項目に同義語を追加**：項目を検索 → 開く →「同義語」に追加 →「保存」。次回から、要件にその言葉が出てくると認識されます
- **変更を取り消す**：オブジェクトや項目の「変更履歴」で「取り消す」をクリック

### 3.6 カタログの変更を全員に反映する

1. 「項目カタログ」→「管理」→「catalog.js を書き出す」
2. ダウンロードしたファイルでリポジトリの `data/catalog.js` を置き換え、コミットしてデプロイします
3. アプリに戻り、「管理」→「この端末の変更をすべて消す」を実行します（新しい同期レイヤーと二重にならないようにするため）

別の PC で作業を続けるだけなら、「変更だけを書き出す（JSON）」と「変更を読み込む（JSON）」で十分です。

### 3.7 表示を調整する

- 背景の明るさ：サイドバー下部の緑の球をドラッグ。ダブルクリックで既定のグレーに戻ります
- 全画面表示：「全画面表示」をクリック、または `F11`
- iPhone 表示：サイドバー下部の「iPhone 表示」をクリック。戻すときはウィンドウ右上の「デスクトップ表示」
- 左上のマークを変更：正式なロゴのファイルを `icons/logo.svg` と `icons/logo-dark.svg` に置いて再読み込み

## 4. データの保存場所

以下のデータはすべて**このブラウザ**（localStorage）に保存されます。どこにも送信されず、ほかの PC やブラウザとも同期しません。ブラウザのデータを消去すると、これらも消えます。

| データ | 内容 |
| --- | --- |
| 履歴 | 検証した設計案（最大 50 件） |
| カタログの変更 | オブジェクトと項目の変更・追加・削除、および変更履歴 |
| 表示の設定 | 背景の明るさ、デスクトップ表示／iPhone 表示、プロンプトにカタログ全体を含めるかどうか |

## 5. 実行とデプロイ

### ローカルで開く

`index.html` をダブルクリックします。`index.html`、`data/`、`icons/` は同じフォルダに置いてください。

リポジトリの Settings → Pages → Source で Deploy from a branch を選び、Branch で `main` と `/ (root)` を選びます。デプロイ後はブラウザからアプリとして「インストール」でき、全画面で開けるほか、オフラインでも使えます。

### デプロイ済みのバージョンを更新する

ファイルを変更したら、`sw.js` の `VERSION` を 1 つ上げてください（例：`v16` → `v17`）。上げないと、ブラウザのオフラインキャッシュが更新されません。ローカルで変更を確認するときは、`Ctrl+F5` で強制的に再読み込みします。

## 7. 設計案 JSON の形式

分岐の数は JSON の内容どおりに表示・検証されます。`branches` の 1 つ目が IF、2 つ目以降がすべて ELSE IF、`else` がどれにも当てはまらないときの処理です。

```json
{
  "intent": "入社時に、雇用区分に応じて試用期間終了日を設定する",
  "base_object": "EmpJob",
  "event": "onSave",
  "attach_to": "職務情報の保存時",
  "branches": [
    {"if": {"all": [
       {"left": {"field": "EmpJob.event"}, "op": "eq", "right": {"picklist": "event", "codes": ["H"]}},
       {"left": {"field": "EmpJob.employeeClass"}, "op": "eq", "right": {"picklist": "employeeclass", "codes": ["2"]}}
     ]},
     "then": [{"set": "EmpJob.probationPeriodEndDate", "value": {"fn": "Add Months", "args": [{"field": "EmpJob.startDate"}, {"const": 1, "type": "number"}]}}]},
    {"if": {"any": [ ... ]}, "then": [ ... ]}
  ],
  "else": [{"set": "EmpJob.probationPeriodEndDate", "value": {"const": null, "type": "date"}}],
  "assumptions": [],
  "field_resolutions": [{"concept": "雇用区分", "kind": "similar", "ref": "EmpJob.employeeClass", "confidence": 0.86, "alternatives": []}],
  "new_config_needed": [],
  "risks": []
}
```

- 条件のグループ：`all`（かつ）または `any`（または）。互いに入れ子にできます
- `op`：`eq` `ne` `in` `notIn` `gt` `lt` `ge` `le` `isNull` `isNotNull`
- 値の書き方は 5 種類：`{"field"}`、`{"const","type"}`（`null` は空欄にする）、`{"picklist","codes"}`、`{"eventReasons"}`、`{"fn","args"}`（関数は入れ子にできます）
- AI がよく使うほかの書き方も受け付けます：`if` / `then` / `else`、または `if` / `then` と `else_if` のリスト。どちらも自動で分岐に変換されます
- 不明なキーは黙って無視せず、エラーとして報告します
